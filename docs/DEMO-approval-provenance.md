# 演示：审批来源快照（G3）

> 对应决策：docs/DECISIONS.md 的 G3；契约：docs/CONTRACT.md 2.5、5.3。
> 目标：删除或重建拦截规则后，历史审批仍能说明当时命中了哪条规则。

## A. 自动化路径（当前环境可跑通）

   go test ./db -run TestApprovalRuleName -count=1 -v

预期：TestApprovalRuleNameFallsBackToAuditSnapshot 通过。它验证：
- 规则存在时，列表返回当前规则名「当前规则名」；
- 删除规则后，列表与详情返回 audit 快照「快照规则名」；
- 没有 audit 快照的旧记录返回空串（前端仍回退「规则未记录或已删除」）。

失败判定：删除规则后返回空串或当前名；正常记录显示变化。

## B. 界面路径（需要已配置模型）

1. 在「系统设置 → 拦截规则」创建一条 ask 规则，名称记为 R1。
2. 触发一次命中（例如让 Agent 执行匹配命令），审批页出现待审批记录。
3. 在拦截规则页删除 R1。
4. 打开「审批记录」，定位该条记录。
5. 预期：规则列仍显示 R1（来自 audit 快照），而不是「规则未记录或已删除」。
6. 打开详情，审计 JSON 的 rule_name 与页面一致。

## 回滚

- git revert 27919c6，恢复只 join 当前规则表的查询。
- 数据无迁移；audit 快照本来就在行内。

## 已知边界

- 如果历史记录产生于快照字段上线之前（audit 无 rule_name），删除规则后仍无法显示来源；这是数据缺失，不做推断。
